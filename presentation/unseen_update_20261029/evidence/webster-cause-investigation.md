# Webster 장시간 정지 원인 진단

작성2026-10-29. 사용자 요청: 왜5분간 차량이 움직이지 않았는지 실제 원인을 조사한다.

- 목표: 보존된5개 실패를 원래 실패 시점까지 재현하고, 원래와 일치하는 운행에 한해 추가 위치/간격/신호/선행차 자료로 정지 원인을 좁힌다.
- 선행: 원래162시도·157완료/5Webster실패·웹 단계까지 완료했고 원시/동결/기존 검토를 보존했다.
- 변경: 진단 전용 도구·새 출력·이 문서/상태 기록만 추가한다. 기존 모델/정책/관측/도로망/수요/신호 제약/teleport 설정과 생산/독립 검증 소스는 변경하지 않는다.
- 새 출력: `results/runs/unseen_webster_cause_20261029/`. 공식 비교·웹 결과를 덮어쓰거나 새 성능 표본으로 합치지 않는다.
- 한도: 실패5조건의 동일Webster 각1회, 원래 최초teleport 시점까지 최대5회. 동시에 운행하지 않는다. 이 추가 진단은 이전182시도와 별도의 사용자 요청 범위다.
- 수집: 원래 매초 프레임/관측/행동에 더해 차량 위치·차로 위치/길이/간격, 해당 차량의 앞차·다음 신호·진행 가능한 차로·교차로 양보 차량을 읽기 전용으로 기록한다.
- 검증: 기존 실패 프레임·모든 정책 결정·신호·차량 속도/대기·도착/유입/이벤트가 매초 원본과 같은지 확인한다. 추가 조회로 재현이 달라지면 그 자료로 원본 원인을 단정하지 않고 중단한다.
- 중단: 원래와 다른 이벤트/관측/제어/입력/소스, 추가 실행 오류 또는 충돌이면 후속 진단을 중단한다. 원래 최초teleport는 예상 종료 사건이며 이를통해 운행을 계속하지 않는다.
- 완료: 확인된 정지 기전과 추정/미확정 원인을 구분해 간단히 설명하고 근거·명령·한계·다음 작업을 기록한다.

기존 로그에는 녹색·교차로 내부 비어 있음·수신 차로 차량 수 감소에도 정지한 사례가 있다. 따라서 ‘모두 신호 녹색이 겹치지 않아 정체’라는 단일 설명으로 확정하지 않는다.

## 1차 진단 저장 및 후속 인계

2026-10-29 사용자 지시에 따라 여기까지의 자료를 저장하고 발표 준비로 전환한다. 우리 모델에서도 같은 정체 기전이 발생할 수 있는지 점검하는 작업과 개선안 검토는 추후 수행한다.

5조건을 추가 조회만 넣어 원래 최초teleport까지 각각1회 재현했다. 모든 기본 프레임·제어 결정·신호·SUMO 경고 로그가 원래 파일과 바이트 단위로 같고 차량별trip 기록도 일치했다. 추가 관측이 원래 운행을 바꾸지 않았음을 확인했다.
원래5실패와 같은2846초/2851프레임/1144교차로 결정을 확인했다. 기존182교통시도와 별도5진단을 합쳐187시도이며, 새로운 독립 성능 표본으로 세지 않는다.

각 차량이300초 연속 정지한 구간만 집계했다. 녹색 때 교차로 건너편에 차량과 기본 안전 간격이 들어갈 공간이 없었고, 해당 기본 공간이 생긴 시점은 녹색이 아니었다. 녹색 중 조회된교차로 양보 상대·자발적 정지 플래그는 모두0이었다.
이는 [SUMO의 교차로 막힘 방지 규칙](https://sumo.dlr.de/docs/Simulation/Intersections.html)과 일치하는 관찰이다. 차량의기본 공간은 [차량 길이와minGap](https://sumo.dlr.de/docs/Definition_of_Vehicles%2C_Vehicle_Types%2C_and_Routes.html)의 합으로 계산했다.
첫 사례에서는 버스가230~235초 양쪽 녹색에도 연결 입구의4.58m로 진입할 수 없었고,300초의빈 차로에는 자기 신호가 적색이었다. 다음395~410초 녹색에는 다른 진입 방향에서 온 차량이 있어 빈 공간이11.58m로 부족했다.

이 결과는 기본 진입 공간 부족과 신호 시점의 불일치를 확인한 것이다. SUMO 내부 C++의 특정 판정 분기를 계측하거나, 앞 도로 정체가 형성된 모든 구조적 원인을 개별 분리한 결과로 확대하지 않는다. 우리 모델의 다른 부하·시간 조건에서 같은 문제가 발생하지 않는다는 보장도 아니다.
