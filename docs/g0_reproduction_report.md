### 경고의 원인

[신호 원본](../network/intersection.net.xml)의 phase 4·9는 전체 적색이다.
직전 phase 3·8에서는 직진·좌회전 쪽 황색과 별개로 우회전 신호 네 개가
여전히 `g`다. 이 네 신호가 황색 없이 적색으로 바뀐다.
SUMO 메시지는 그중 첫 link인 0을 표시하며, XML 비교에서는 0·3·6·9 모두 확인된다.

신호 복사본의 두 단계만 수정한 실험으로 경고가 사라지는 것을 확인했다.
이는 원인 분리 실험이며, 수정안을 원본에 적용하거나 차량 충돌 안전성을 검증한 것은 아니다.

### AI 실행 경로는 XML 정적 프로그램과 다르다

설치된 sumo-rl 1.4.5의 `environment/traffic_signal.py` 기준:

- `_build_phases()` 107~140행은 녹색 4개만 추출하고 황색을 새로 생성한다.
  XML에 있던 전체 적색 단계는 포함하지 않는다.
- 환경 기본 `yellow_time=2`가 사용된다. XML 정적 프로그램의 황색 4초와 다르다.
- `set_next_phase()` 158~177행은 같은 녹색 요청을 계속 허용한다.
  `max_green`은 저장되지만 이 전환 조건에서 사용되지 않는다.
- `update()` 147~156행은 황색 이후 바로 다음 녹색을 적용한다.
- 우회전 네 신호는 추출된 모든 녹색 단계에서 `g`이고, 실행 기록에서도 계속 `g`다.
  따라서 XML 정적 프로그램의 우회전 `g→r` 경고를 AI 실행의 같은 전환으로 해석하면 안 된다.

Next를 반복했을 때 실제 신호는 다음과 같다. 숫자는 **AI 녹색 인덱스**이며 XML phase 번호와 다르다.

```text
0~20초: 녹색 0 → 20~22초: 황색 → 22~40초: 녹색 1
40~42초: 황색 → 42~60초: 녹색 2
60~62초: 황색 → 62~80초: 녹색 3
80~82초: 황색 → 82~100초: 녹색 0
```

`smart_signal.py`의 학습을 실행하지 않고 AST로 관측→현재 단계·Keep/Next 변환 함수만
읽어 실제 함수를 사용했다. 제어기는 그대로 두고 매초 신호 상태를 읽는 기록 기능만 붙였다.
전체 적색 자동 적용을 적은 `smart_signal.py` 주석과 실제 동작은 일치하지 않는다.
학습·데모·평가가 같은 환경 설정을 사용하지만, 이번에는 각 프로그램 전체를 실행하지 않았다.
