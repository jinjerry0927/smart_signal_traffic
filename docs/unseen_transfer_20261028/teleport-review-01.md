# 중단 원인·미실행 조건 후속 배치 별도 검토 01

검토자: Codex. 외부 사람의 검토가 아니라 원시 기록 재계산·소스 검토를 분리한 기록이다.
기준: 기존 protocol/freeze/evaluation-review-v2와 사용자의 ‘Codex가 별도 검토 기록을 남긴 뒤 연속 실행’ 답변.

## 실제 중단과 확인 결과

본 시험 128번째 `zt_pair_short_busy_s00/webster`가 SUMO 시간503초에 버스 `veh_00106`의 `yield` teleport를 기록했다.
이벤트는 다음 관측504초에 수집됐고 즉시 해당 운행과 후속 배치가 중단됐다. 완료127회/실패1회/미실행34회다.
완료127회의 원시 파일·검증서 SHA를 다시 대조했고, 실패 운행의505프레임·202결정을 독립 시계·관측·Webster 산술로 재계산해 일치를 확인했다. 충돌0/teleport1이다.
[기계 판독 진단](teleport-diagnosis.json)과 원래 `final/batch-v2.json`을 보존한다.

버스는 `zt_b_E_in → zt_link_in → zt_a_E_out` 경로를 따른다. 두 회전 사이의 연결 차로1이 일치해 필수 차로 변경이나 경로 단절은 발견되지 않았다.
204~503초의300개 연속 시점에서 속도는0.1m/s 미만이다. 이 기간 상류 동쪽 녹색은204~235/395~410초, 하류 북쪽 녹색은230~265/440~455초다.
상류 녹색 동안 수신 차로1에13~15대가 있었다. 녹색 시점 불일치와 연결 차로 혼잡이 통과 기회를 제한했을 가능성이 있다.
위치·선행차·실시간 간격 자료는 수집하지 않아 정확한 양보 판정의 직접 원인은 확정하지 않는다.

SUMO는 장시간0.1m/s 미만 대기 시 기본300초 기준으로 teleport하며, `yield`는 우선 교통에서 간격을 찾지 못한 경우의 분류다.
따라서 로그를 단순한 경로 오류나 검증기의 오탐으로 바꿔 기록하지 않는다. [SUMO 공식 설명](https://sumo.dlr.de/docs/Simulation/Why_Vehicles_are_teleporting.html).

## 후속 실행 판단과 범위

사용자가 이미 요청한162개 비교의 나머지34개를 수집한다. 모델·기준선·도로망·수요·제약·시간·성능 기준을 바꾸지 않고, 이미 시도한 실패 운행은 재실행하지 않는다.
원래 실패 배치는 재개하거나 성공으로 고치지 않는다. 새 `followup_round01/`에 명시된 미실행 접미 조건만 넣는다.
이는 중단 진단 후 수행하는 별도 후속 자료이며 원래 사전 명세의 전체 통과 증거로 합치지 않는다.
기능3+예비12+본 비교 시도162=최대177회 한도를 유지한다. 추가 학습·재선정0이다.

오류·충돌·teleport·식별/원시 불일치가 발생하면 후속 배치 전체를 다시 멈춘다. 실패 자동 재시도·실패 배치 자동 재개는 없다.
추가 후속 배치는 새 원시 진단과 별도 검토 기록을 요구한다. 최초 `followup-proposal.json`은 미실행 초안이며 이 검토와 실제 동결된 후속 명세를 기준으로 한다.

## 실행 코드 검토

- 기존 동결 생산/검증 소스4개와 기준 모델/규칙/기본 소스17개를 변경하지 않는다.
- 별도 `unseen_transfer_followup.py`가 기존 `run_one`과 독립 `verify_run`을 호출한다. 새 배치의 소스·검토 문서·부모 배치·실패 원시 SHA를 고정한다.
- 시도 목록은 원래162개 순서의 정확한 접두여야 한다. 중복·건너뜀·실패 재시도·추가 조건을 거부한다.
- 실패 prefix는 신호·관측·마스크·신경망/정책을 따로 재생하고, 마지막 시점의teleport/충돌0과 정상 종료된 기록을 확인한다.
- 실패 부분 지표를900초 완료 지표로 만들지 않는다. 최종 표에는 모든 시도 상태를 넣고, 평균은 명시된 공통 완료 조건 또는 제어별 짝만 사용한다.
- 원래 주 목표 통과 여부는 `null`/평가 불완전으로 남긴다. 후속 서술 통계와 학습 기여 비교를 구분한다.

신규 검사5개는 순서·재시도 거부, 검토 변조 차단, 실패 배치 재개 거부, 실패 원시 SHA 고정,161완료/1실패 보고의 공통26조건·짝별26/27조건 구분을 확인한다.
첫 검사 실행은 CSV 기대 문자열의 경로 누락으로1개 실패했고 실제 데이터/소스에 영향을 주지 않았다. 기대 문자열 수정 후5개 PASS를 확인한다.

## 재현 명령

번들 Python의 `-X utf8 -B`로 실행한다.

```text
tests/test_unseen_transfer_followup.py
tools/diagnose_unseen_transfer_stop.py
tools/unseen_transfer_followup.py prepare --round 1 --note docs/unseen_transfer_20261028/teleport-review-01.md
tools/unseen_transfer_followup.py run --round 1
```

진단 명령은 최초1회 실행했고 기존 진단 파일이 있으면 덮어쓰기를 거부한다.
판정: 원시·제어 정합성과 실패 보존 조건을 확인한 후, 미실행34회만 별도 수집하도록 통과. 원래 본 시험 성공 판정은 아님.
