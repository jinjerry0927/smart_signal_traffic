# 중단·미실행 접미 배치 검토 02

검토자 Codex. 사용자의 별도 Codex 검토 후 연속 비교 요청 범위에서, 아직 시도하지 않은28개 비교만 수집한다.
원래 본 배치·후속01은 모두 실패 상태 그대로 유지한다. 모델·규칙·도로망·수요·시간·성능 기준의 변경이나 실패 재실행은 없다.

## 두 번째 실패 확인

후속01은5회 완료 뒤 `zt_pair_short_busy_s01/webster`에서 멈췄다. 전체 예정 비교는132완료/2실패/28미시도다.
승용차 `veh_00260`은321~620초의300개 연속 관측에서0.1m/s 미만이고,620초 마지막 사전 관측의 대기는300초다.
SUMO620초의 `yield` teleport가621초 관측에 기록됐다.622프레임/250개 결정을 독립 재계산했고 신호·관측·정책이 일치했다. 충돌0/teleport1이다.
[진단 원본](teleport-diagnosis-02.json)에 실패 원시 파일 SHA를 보존한다.

대기 중 상류 서쪽 녹색은321~325/490~545초, 하류 남쪽 녹색은375~400/570~620초로 서로 겹치지 않는다.
상류 녹색의 모든 관측에서 수신 연결 차로1에15대가 있었다. 신호 시점 불일치·연결 차로 혼잡에 부합하는 패턴이다.
경로는 `zt_a_W_in → zt_link_out → zt_b_E_out`이다. 진입은 연결 차로1, 다음 우회전은 차로0이므로 이 차량에는 연결로 안에서1→0 차로 변경이 필요하다.
첫 실패의 ‘필수 차로 변경 없음’을 이 차량에 적용하지 않는다. 정적 차종/경로·저부하 기능 검사는 통과했으나 혼잡 중 차로 변경 영향과 직접 양보 간격 원인은 미확정이다.

## 별도 검토 판단

경로를 재설계하거나 수요·teleport 기준을 완화하면 최종 시험 입력이 달라진다. 그런 보완은 이번 비교에서 하지 않는다.
다른 제어는 같은 입력의 첫 혼잡 표본에서 완료했으며, 두 번째 표본의 나머지 제어는 아직 시도하지 않았다. 비교에 필요한 기존 예정 접미 조건을 수집하는 것이 다음 조사다.
동결 소스4개/기준17개·후속 실행 소스·이전 검토 원문 해시를 확인하고, 실패 원시 SHA와 시도 순서를 새 명세에 고정한다.
운행이상 발생 시 전체 배치 중단과 새 검토를 다시 요구하며, 이미 실패한 운행의900초 지표를 만들지 않는다.

판정: 원래 전체 목표는 통과 처리하지 않는다. 이전 실패2회를 남긴 채 미시도28회만 `followup_round02/`에서 수집하는 별도 배치에 한해 통과한다.
검사5개는 직전 소스와 동일하며 추가 소스 변경이 없다. 생성 명세와 이 검토를 고정한 후 아래 순서로 실행한다.

```text
tools/unseen_transfer_followup.py prepare --round 2 --note docs/unseen_transfer_20261028/teleport-review-02.md
tools/unseen_transfer_followup.py run --round 2
```
