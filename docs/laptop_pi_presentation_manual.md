## 2. 발표 당일 가장 쉬운 실행

1. 휴대폰 핫스팟을 켠다. 노트북과 Pi가 모두 같은 핫스팟에 연결돼야 한다.
2. Pi 전원을 연결하고 몇 분 기다린다. 첫 부팅은 더 오래 걸릴 수 있다.
3. 휴대폰의 연결 기기 목록에서 Pi IP를 확인한다. 기기 이름은 `jinjerry`일 수 있다.
4. 프로젝트 폴더에서 **`start_demo_pi.cmd`를 더블클릭**한다.
5. IP가 같으면 Enter, 달라졌으면 현재 IP를 입력하고 Enter를 누른다.
6. SSH 창이 새로 열리면 새 Pi 비밀번호를 입력한다. 서버가 이미 실행 중이면 이 단계는 생략된다.
7. 자동으로 열린 브라우저에는 Pi 주소와 원격 모드가 자동 입력된다. 아래 설정을 확인하고 **Pi 연결 확인**을 누른다.

| 웹 메뉴 | 선택 |
|---|---|
| 교통 상황 | 혼잡한 교통 |
| 신호 체계 | Smart Signal |
| 추론 위치 | 원격 / Raspberry Pi |
| 추론 서버 주소 | `http://현재_PI_IP:9998` |
| 재생 속도 | 30배 · 빠른 시연 (신호 설명은1배, 더 빠른 확인은60배) |
| 실험 시간 | 300초 · 빠른 시연 |

**Pi 연결 준비 완료 · 모델 일치**를 확인한 뒤 **실험 시작**을 누른다.
300초는 시뮬레이션 시간이며,30배에서는 실제 약10초에 계산·통신 시간을 더한 시간이 걸린다.
실행 중에도 재생 속도를 바꿀 수 있다. 신호를 설명할 때는1배로 내리고 일시정지한다.
웹 상단의 **이번 실험 계산: Raspberry Pi**와 **원격 추론 · jinjerry** 표시를 확인한다.
`PC 대체 추론`이 보이면 현재 Pi 추론을 쓰지 않는 상태다.
발표 중 노트북 실행 창과 Pi SSH 창을 열어 둔다.

웹 포트8000이 사용 중이면 도우미가8001~8010 중 빈 포트를 선택한다.
실행 창에 표시되는 웹 주소를 사용한다. 기존 프로그램은 자동 종료하지 않는다.

## 3. 발표 진행 순서와 설명

1. 실행 전에 “노트북이 교통을 진행하고, Pi가 AI 판단을 계산합니다”라고 설명한다.
2. 상단의 **관측 → AI 계산 → 안전한 신호 적용** 흐름을 설명한다. 차량 이동, 대기 차량 수, 도착 수를 보여준다.
3. 교차로 이름을 눌러 지도를 확대한다. 마우스로 끌어 상하좌우 이동하고 휠로 확대한다. 지도를 클릭한 뒤 방향키로도 이동할 수 있다. **전체 지도** 버튼으로 복귀한다.
4. 필요하면 **일시정지 → 재개**를 사용한다. **정지**는 이번 실행을 종료한다.
5. 300 / 300초와 **실험 완료**가 나타나면 결과를 설명한다.

발표용 설명:

> 여러 가상 교차로에서 학습한 공통 AI 모델이 현재 교통 관측을 받아 신호를 선택합니다.
> 노트북은 SUMO와 웹 관제를 실행하고, Raspberry Pi는 AI 추론을 담당합니다.
> 황색과 전체 적색 같은 안전한 전환은 노트북이 유지합니다.
> 아래 비교표는 별도로 저장된 가상 수요 실험 결과이며, 지금 시연 수치와는 구분합니다.

실험 종료 시 도로에 차량이 남아 있을 수 있다. 이는300초 시간 제한에 따른 결과다.
가상 교통 실습이며 실제 도로 신호 장비를 제어하지 않는다.

## 4. PC만으로 시연하기

Pi 연결에 문제가 있거나 PC와 Pi를 비교하고 싶으면 **`start_demo_pc.cmd`를 더블클릭**한다.

상단에 **실제 계산: PC**가 보여야 한다.

같은 입력의 PC/Pi 행동은 같아야 하며, 통신을 포함한 결정 시간은 서로 다를 수 있다.
PC 시연을 Pi 시연으로 설명하지 않는다.

```powershell

```

Pi에 접속한다. IP가 바뀌면 실제 IP로 바꾼다.

Pi에 로그인된 터미널에서 실행한다. 이 두 명령은 Windows 창에 직접 입력하는 명령이 아니다.

```bash

python3 -B -m signal_demo edge --release release --host 0.0.0.0 --port 9998
```

`Edge ready`가 나오면 준비 완료다. 이미9998서버가 실행 중이라면 중복으로 실행하지 않는다.

**별도의 노트북 PowerShell 창**에서 웹 관제를 실행한다.

```powershell
cd C:\Users\jinuk\Documents\GitHub\sumo_project
& .\.codex-artifacts\demo311\Scripts\python.exe -X utf8 -B demo_web_pi.py --port 8000 --out results/runs/laptop_presentation
```

8000이 사용 중이면 `--port 8001`로 바꾼다. 브라우저에서 해당 포트의 주소를 연다.
각 실행은 자동으로 새 날짜·UUID 폴더에 저장된다.

## 6. 발표 전 확인

브라우저에서 `http://현재_PI_IP:9998/health`를 열어 `status: ready` 응답을 확인할 수 있다.
서버만 준비된 것과 실제 웹에서 Pi가 사용되는 것은 다르므로, 시연 중 원격 연결 표시도 확인한다.

PC/Pi 300개 행동 일치 검사를 다시 하려면 **노트북 PowerShell**에서:

```powershell
cd C:\Users\jinuk\Documents\GitHub\sumo_project
$probeTime = Get-Date -Format yyyyMMdd_HHmmss
& .\.codex-artifacts\demo311\Scripts\python.exe -X utf8 -B -m signal_demo probe --url http://10.64.217.27:9998 --out "results/runs/pi_probe_$probeTime.json"
```

`Remote parity passed: 300 actions`가 나오면 통과다. 녹색·황색·전체 적색 입력을 포함한다.
IP가 바뀌었다면 검사 주소도 바꾼다. 매번 새 출력 이름을 사용한다.

기록은 새 실행 폴더의 `manifest.json`, `metrics.json`, `decisions.csv`, `signals.csv`에 남는다.
Pi 시연에서 `decisions.csv`의 `inference`가 전부 `edge`이고,
`manifest.json`의 `fallback_events`가 빈 목록이어야 전체 시연에 실제 Pi가 사용됐다.

## 7. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| 비밀번호 입력 글자가 안 보임 | 정상이다. 새 비밀번호를 입력하고 Enter. Windows 입력기를 영어로 전환한다. |
| `Permission denied` | 계정은 `james`. Pi에 새로 설정한 비밀번호를 사용한다. 창이 이미 종료됐다면 도우미를 다시 실행한다. |
| SSH 연결 시간 초과 | 현재 IP, 두 장치의 핫스팟 연결, Pi 전원·부팅을 확인한다. 핫스팟에서 기기 간 통신을 막는 설정도 확인한다. |
| IP가 달라짐 | 도우미에 새 IP 입력. 웹 서버 주소와 probe 주소도 새 IP로 변경한다. |
| 처음 보는 IP의 SSH 서버 키 확인 | 먼저 `ssh james@현재_IP`로 직접 접속해 본인의 Pi임을 확인하고 서버 키를 등록한다. |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | OS를 재설치했거나 다른 기기가 같은 IP를 받은 경우다. 본인 Pi IP와 재설치 여부를 먼저 확인한다. 확인 후 `ssh-keygen -R 현재_IP`로 해당 IP 기록만 지우고 다시 접속한다. |
| `Address already in use` /9998 사용 중 | `http://현재_PI_IP:9998/health` 확인. 같은 모델 서버가 ready라면 이미 켜져 있으므로 재사용한다. 다른 프로그램은 임의로 종료하지 않는다. |
| `Pi에 연결하지 못했습니다` | 실행 전에 연결 검사에 실패했다. 아직 운행이 시작되지 않았으므로 주소를 고친다. `127.0.0.1`은 노트북 자신이며 Pi IP가 아니다. 또는 **PC로 시연하기**를 직접 선택한다. |
| `PC 대체 추론` 표시 | 실행 중 Pi 연결을 잃었거나 구버전 관제에서 연결 실패를 무시하고 시작했다. 이번 운행은 PC로 대체됐다. Pi 서버/주소를 확인하고, 이번 실행을 종료한 뒤 새 실험을 시작한다. 진행 중 자동으로 Pi로 복귀하지 않는다. |
| 웹에 연결할 수 없음 | 노트북 실행 창이 열려 있는지, 창에 표시된 포트와 브라우저 주소가 같은지 확인한다. |
| Pi 폴더를 찾을 수 없음 | OS 재설치로 삭제됐을 수 있다. 보관한 배포본을 새 폴더에 다시 전송해야 한다. |

발표 중 Pi 연결을 바로 해결하기 어렵다면 PC 모드로 전환하고 이를 설명한다.
화면 공유용 Raspberry Pi Connect와 Pi 모니터는 이번 실습에 필요하지 않다.

## 8. 발표 종료

1. 웹 실험을 완료하거나 **정지**한다.
2. 노트북 웹 실행 창에서 **Ctrl+C**를 눌러 관제를 종료한다.
3. 직접 실행한 Pi 서버 SSH 창에서 **Ctrl+C**를 눌러 서버만 종료한다.
4. SSH 창이 닫혔다면 노트북의 새 PowerShell에서 `ssh james@현재_PI_IP`로 다시 접속한다. Pi 터미널에서 `sudo shutdown -h now`로 안전하게 종료한다.
5. Pi가 종료된 것을 확인한 뒤 전원을 분리한다.

현재 연결 작업에서 시작한 Pi 서버는 SSH 창을 닫아도 유지되지만, Pi를 재부팅하면 종료된다.
재부팅 후에는 `start_demo_pi.cmd`로 다시 시작한다. 자동 부팅 서비스는 설정하지 않는다.

## 신호 카드 읽는 법

- **그룹1~4**: 함께 녹색을 받을 수 있는 방향의 묶음이다. 교차로마다 허용되는 움직임을 설정해 놓았다.
- **녹색 시작 후20초**: 녹색이 켜진 뒤 지난 시간이다. 앞으로20초가 남았다는 뜻이 아니다.
- **황색 종료까지2초**: 황색3초 중 남은 시간을 뜻한다.
- **전체 정지 종료까지2초**: 모든 방향을 잠깐 멈추는 전체 적색2초 중 남은 시간이다.
- **그룹별 정지40초**: 그 그룹이 이미 정지한 시간이다. AI가 다음 그룹을 고르므로 녹색까지 남은 시간은 미리 확정해서 표시하지 않는다.

전환 순서는 **녹색15~60초 → 황색3초 → 전체 정지2초 → 선택한 다음 그룹 녹색**이다.
AI는5초마다 현재 녹색을 유지할지 바꿀지 판단한다. 빠른 배속에서는 화면 갱신 사이에 짧은 전환이 지나갈 수 있다.
신호 설명은1배에서 하거나 **일시정지**로 상태를 고정한다.
