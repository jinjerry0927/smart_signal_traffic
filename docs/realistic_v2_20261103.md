## 목표와 현재 결론

Legacy V1의 관측·추론·정책·안전 시계·모델·수요·연구 결과를 유지하고,
별도 `realistic_signal/`과 `network/realistic_v2/gyeongju/`에 연구용 V2를 추가했다.
용강·승삼은 선행/후행 중복 현시, 근화여고는 양방향 보호좌회전과 양방향 직진을 사용한다.
공유 차로를 분리하지 않은 보조 접근로는 방향별 직·좌·우 동시 보호신호를 유지한다.

구현된 것은 **정적 차량 상충표에 근거한 제어 환경**이다. 현장 신호계획이나 차량 운행의 안전성을
검증한 결과가 아니다. 기존 seed43 모델은 재학습 없이 계산·선택할 수 있지만,
새 행동과 관측 분포에 대한 성능·전이 타당성은 검증되지 않았다.

직·좌 분리, 직·좌 동시, 선행/후행 중복이라는 운영 방식의 구분을 설계에 사용했다.

위 표의 채택 여부는 저장소 기하와 정적 상충 검사에 따른 프로젝트 설계 판단이다.
최소녹색 15초, 최대 60초, 황색 3초, 소거 2초는 기존 연구의 제한값을 유지한 실험값이다.
접근 속도·교차로 폭·보행 횡단시간으로 현장 산정한 시간은 아니다.

## 기존 구조와 차로 제약

원본 `intersection.json`은 교차로마다 N/E/S/W 4후보, 총 42연결이다.
각 후보는 한 접근로의 모든 이동을 `G`로 켠다. N/S 2차로는 바깥 0차로 직진·우회전,
안쪽 1차로 직진·좌회전 공용이다. 용강 E는 2차로(0 직진·우회전, 1 좌회전),
나머지 E/W와 용강 W는 1차로 직진·좌회전·우회전 공용이다.
원본 상태에서 N/S 직진과 좌회전을 독립 점등하면 공유차로 선두 차량이 다른 이동을 막는다.

산업로 내부 연결은 `yonggang_geunhwa`, `geunhwa_seungsam`이며 모델의 N/S축이다.
승삼 북측은 산업로 연장, 근화여고 E/W는 보조 진입로다.
**용강에서는 원본 layout의 E가 산업로 남동 방면, S가 원화로 방면, W가 유림로 방면이다.**
따라서 용강의 실제 산업로 접속은 N/E이고, 본 망의 N-S 직진축과 같다고 해석하면 안 된다.
V2는 도로의 곡선·교차부와 기존 회전 정의를 보존한다. 용강 E의 우회전·직진 공용차로 때문에
E→N 산업로 우회전만 독립 녹색으로 허용하는 기능은 채택하지 않았다. E 방향은 별도 보호 그룹으로 제공한다.
신호 연동·오프셋·실측 수요에 따른 주축 우선 최적화는 하지 않았다.

V2는 세 교차로 N/S 안쪽 차로의 직진 연결만 총 6개 제거하고 좌회전 전용으로 사용한다.
물리 차로 수 30, 외부 도로 20, 기존 OD 경로와 차량 출발 일정은 유지한다.
`netconvert`로 내부 연결과 `request/foes`를 다시 계산했다. 완성된 `.net.xml` 문자열만 바꾼 것이 아니다.
차로 추가·도로 확폭은 없다. 해당 접근로 직진 차로는 2개에서 1개가 되어 연구 가정의 명목 직진 포화교통량은
3,600→1,800대/시로 감소한다(차로당 1,800 가정). 좌회전은 독립 차로를 얻는다.
이 수치는 차로 배분의 설명이며 실제 처리량이나 개선율이 아니다. 좌회전 포켓 길이·차로변경·역류 영향은 운행 미검증이다.

교차로별 원본 차로·V2 현시·진입/진출 차로·상충 상대·선후행·전환 조건은
[신호계획 상세표](realistic_v2_signal_plan.md)에 전수 기록했다.

## 이동별 안전 계층

Legacy `SignalClock`은 전체 녹색→전체 황색→전체 적색으로 전환하므로 직진 유지가 불가능하다.
새 `MovementClock`은 현재/목표 그룹의 공통 녹색은 유지하고, 종료 이동만 3초 황색→2초 적색 소거한다.
새로 시작하는 이동은 그 뒤에만 녹색을 받는다. 소거 중에도 공통 이동이 녹색일 수 있어 상태 이름은
`all_red` 대신 `clearance`다. 모든 전환에서 황색 이동과 유지 녹색까지 함께 상충 검사한다.

망에서 TLS 인덱스를 실제 내부 junction request 인덱스로 매핑하여 양방향 `foes`를 확인한다.
서로 다른 진입 차로가 같은 진출 차로로 합류하는 쌍도 충돌로 취급한다.
공유 진입 차로의 이동은 항상 같은 색이어야 하고, 모든 이동에 서비스 그룹과 정지 그룹이 있어야 한다.
허용하지 않은 문자·그룹·행동·중간 전환 변경은 거부한다. spec은 매 로드 때 망에서 재생성하여 완전 비교한다.

연속 녹색은 현시 이름이 바뀌어도 이동별로 누적한다. 다음 현시에서 유지될 녹색에는
소거시간과 다음 최소녹색까지 남아 있는지 검사한다. 60초 도달 시 호출자가 선택을 빠뜨려도 안전 전환한다.
새로 시작한 이동은 다음 그룹 최소 15초 전에 끊을 수 없다.
최장 미서비스 이동을 180초보다 앞서 우선하도록 예약 여유를 둔다.
이는 차량 개별 최대 대기시간 보장이 아니다. 단위 시험에서 장기 유지/무작위 선택의 미서비스 상한을 확인했지만
모든 수요의 지체·차로 대기·네트워크 역류를 보장하지 않는다.

Fixed/Webster의 기본 그룹 순서는 상세표를 따른다. 안전 마스크가 연속녹색·장기 미서비스를 제한하면
기본 순서나 목표 지속시간보다 안전 조건을 우선한다. AI/Max-Pressure는 안전 후보 중 자유롭게 선택하므로
중복 현시의 세 그룹을 매번 모두 거친다고 보장하지 않는다.
망 자체의 독립 정적 프로그램은 녹색 15초, TraCI Fixed는 기존 25초 목표와 안전 마스크를 사용한다.
두 실행 방식의 현시 지속시간을 같은 결과로 비교해서는 안 된다. 안내 명령은 모두 TraCI 제어기를 사용한다.

## 우회전 범위

[경찰청 우회전 안내](https://www.korea.kr/multi/visualNewsView.do?newsId=148914126)는 전방 적색 시 일시정지,
횡단하거나 횡단하려는 보행자 보호, 전용 신호가 있으면 그 신호 준수를 안내한다.
도로교통법 제27조의 보행자 보호 의무도 고려 대상이다.
현재 망에는 보행자·횡단보도·횡단 의도 관측이 없으므로 **전체 국내 우회전 규칙을 구현했다고 볼 수 없다.**

[SUMO 공식 문서](https://eclipse.dev/sumo/docs/Simulation/Traffic_Lights.html#signal_state_definitions)에서
`G`는 우선권 녹색, `g`는 상충 우선 차량에 양보하는 녹색, `s`는 정지 후 우회전 상태다.
[동일 문서의 우선권 설명](https://eclipse.dev/sumo/docs/Simulation/Traffic_Lights.html#interaction-between-signal-plans-and-right-of-way-rules)은
새 `g/G` 관계에 내부 우선권 재계산이 필요함을 명시한다.
V2는 `g/s`를 사용하지 않는다. 우회전은 비상충 보호 `G`에서만 가능하고 적색은 정지다.
별도 우회전 전용 신호등이 현장에 있다고 가정하거나, 녹색이면 보행자까지 안전하다고 주장하지 않는다.

## AI·웹·Pi 호환성

| 항목 | Legacy V1 | Realistic V2 |
|---|---|---|
| 모델/정책 | 동결 seed43 / Adaptive V2 | 동일 가중치·점수 계산·보정 로직을 실험적으로 재사용 |
| 행동 | 방향별 4그룹 | 근화여고 4, 용강/승삼 5그룹; 의미 변경 |
| 7입력·후보 평균 | 기존 계산 | 동일 특징 목록·정규화·후보 평균; 후보 차로와 다운스트림 구성이 변경 |
| 시간 특징 | 현시별 경과·미서비스 | 이동별 누적 녹색과 그룹 구성 이동의 최대 미서비스 반영 |
| 압력·관측 수집 | 기존 동결 코드 | 같은 수집기 기반; 해당 그룹에 켜진 이동의 진출 차로만 평가 |
| 전환 | 전체 황색/적색 | 종료 이동 황색/소거 + 공통 녹색 유지 |
| 비교 제어기 | Fixed/Webster/Max-Pressure | 같은 제어기 + 새 안전 마스크; 성능 비교 미실행 |
| Pi | 기존 프로토콜 유지 | 미지원, PC 실험 전이만 허용 |
| 검증된 과거 성능 | 저장된 기존 비교 범위 | 없음; 웹의 과거 비교표는 Legacy V1 결과 |

가변 후보 수를 처리하는 공유 scorer이므로 4/5후보에서 유한 점수와 합법 행동을 계산할 수 있음을
가짜 차로 관측으로 시험했다. **7차원이 같다는 사실은 모델 적합성의 증거가 아니다.**
학습 때 없던 중복 그룹·전용 좌회전·그룹 평균·시간 특징 변화가 정책을 악화시킬 수 있다.
관측값은 미래 route 정답을 사용하지 않는다. 재학습·가중치 변환은 하지 않았다.

웹은 기본 레이아웃과 공통 이동별 SVG 렌더러를 유지한다. opt-in 서버에만 V2 도로망 선택을 추가했다.
선택한 체계와 실제 첫 프레임에서 적용한 체계를 구분하고, 현시 이름·전환 상태·다음 그룹·우회전 제한을 제공한다.
지도 신호는 lane 요약 대신 `state[linkIndex]`를 그대로 사용한다. `unseen_dashboard.html`은 수정하지 않았다.
`--unseen`과 V2는 동시 사용을 거부한다. 기존 신규망 봉인·모델·결과 해시 검사를 완화하지 않았다.

기존 Pi는 Legacy 시계로 마스크와 시간 특징을 재검증하므로 V2 입력을 전송하면 호환되지 않는다.
이를 숨기거나 기존 프로토콜을 느슨하게 하지 않고 V2 원격 실행을 사전 거부한다.
Pi용 V2는 이동 타이머·상충표·계약 식별자를 포함하는 별도 프로토콜과 동작 일치 검증이 후속 조건이다.

- 이 보고서, 상세표, [직접 실행 안내](realistic_v2_manual.md), `README.md`, `STATE.md`.

`transferable_signal/`, `configs/`, 기존 `network/`, 기존 `results/`의 파일 바이트는 변경하지 않았다.
작업 전 1,516개 파일 SHA256 목록을 별도 보관했고 작업 후 전수 비교했다.
기존 release 검사와 원본 모델/정책/추론 소스 해시 검사는 그대로 실행했다.

## 검사와 남은 작업

검사 명령과 최종 결과는 [검증 기록](realistic_v2_validation.md)을 따른다.
기존 전체 테스트에는 학습 검사·신규망 실행환경 조회가 포함될 수 있어 이번에는 관련 경량 검사만 명시적으로 선택했다.
`check --load`, 실제 통합 도구, SUMO 버전 조회 및 브라우저 자동화는 실행하지 않았다.

다음 작업은 [실행 안내](realistic_v2_manual.md)에 따라 사용자가 VS Code에서 운행하고 로그를 제공하는 것이다.
일반/혼잡/방향 편중에서 그룹·이동 신호·차로변경·미진입·잔류·충돌·teleport를 먼저 확인한다.
순수 AI 점수와 보정·안전 제한을 구분하고, 이후 동일 일정에서 기준선 비교를 별도로 설계한다.
그 결과로 재학습 필요성을 판단하며 과거 26.50% 개선 수치를 V2에 전용하지 않는다.
물리 Pi·보행자·조건부 우회전·현장 시간 산정·안전 인증은 미검증/미구현으로 남긴다.
