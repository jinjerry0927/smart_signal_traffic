3. 매초 교차로/차로의 대기·차량·진출 밀도와 실제 신호/Clock을 읽기 전용으로 기록한다.

   현재 정지 시간을 누적 전체 대기로 해석하지 않는다. 교차로 분류는 현재 위치 기준이며 출발 기원과 구분한다.
4. 동일1800초끼리 비교하고, 900초 성능과 연장 성능을 섞어 개선으로 부르지 않는다.
   핵심은 같은353대의 추가 도착/최종 미완료·전원 도착 시각·교차로별 잔류/막힘이다.
5. 목표:prefix 재현·기록/원시 감사 통과와 정리 시간/잔류 병목에 대한 근거 있는 결론.
   전원 도착 여부는 실험 결과이며 기준을 낮추거나 시간 연장을 AI 보완/재학습으로 주장하지 않는다.
6. 오류/충돌/teleport/기록 불일치면 멈춰 진단한다. 급제동은 원시 위치/시각을 보존하고 별도 보고한다.

## 첫 운행의 감사 중단과 최소 보완

첫 Fixed/busy_s00은1800초 운행을 완료했고673대 전원 도착·충돌/teleport/경고0이다.
기록 검사는600초부터 `arrived+running+pending==scheduled`라고 가정해600초 한 행에서 중단했다.
해당 행은286+382+2=670이며, 예정 출발599.127/599.401/599.650초의3대가 아직 출발 시도 전이었다.
601초에288+380+5=673이 되었고 이후 누락은 없다. 설치된 TraCI의 pending은 출발 지연으로 삽입을 기다리는 차량만 뜻한다.
매초 계산은 step이 끝난 뒤 기록하므로 이번 고정600초 미만 출발/1초 step의 전원 계수 검사는601초부터 적용한다.
모든 시각 예정 수 초과 금지·출발/도착 계수·900/1200/1800초 ID 완전 대조는 그대로 유지한다.

원래 운행 도구/실패 출력은 보존한다. 신규 감사 보완 wrapper는 위 조건 한 곳만 바꾸며 운행·관측·정책은 수정하지 않는다.
새 출력 `results/runs/gyeongju_drain_wave4_20261004_retry01/`에서 첫 원시 결과를 동일 SHA로 복사·재검증하고15회만 추가한다.
계획은 총16회이며 기존 첫900초의 완료 차량494대·모든 trip 속성/집계/신호/경고 재현 검사는 이미 통과했다.
실제 관측 코드 SHA와 새 감사 wrapper SHA를 별도로 기록하고, 재사용한 첫 결과의 원본 경로/입력 해시도 명시한다.
