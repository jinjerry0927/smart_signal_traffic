# Smart Signal 최종 프로젝트 차터

기준일: 2026-10-04. 초기 계획 일정은 약 1달 반이며 개발 대부분을 사용자가 진행한다.
지난 학기 차터는 [원본 보관본](../archive/semester1/project_charter.md)에 보존했다.

## 목적

경주의 연결된 교차로를 SUMO로 구성하고, 차량 유입과 이웃 교차로 혼잡을 고려하는
AI 신호체계를 직접 학습한다. 기존 신호와 같은 교통 수요에서 비교하고,
웹 지도와 라즈베리파이 추론 장치로 작동 과정과 결과를 보여준다.

2026-10-01 교수 피드백에 따른 추가 핵심 목표는 **다른 교차로로 옮겨 쓸 수 있는 AI**다.
교차로별 차로·신호 정보를 설정으로 분리하고, 여러 환경에서 배운 공통 모델을
지원 범위 내 새 교차로에 재학습 없이 적용하는 것을 우선 목표로 한다. 범위 밖 환경의 추가 학습은
별도로 구분한다. 학습하지 않은 교차로의 성능은 별도 평가 대상으로 두며 재사용 가능성을
현재 달성한 성능으로 주장하지 않는다. Webster는 교통 입력으로 신호 시간을 산정하는 비교
기준으로 사용하며 모든 혼잡 상황의 자동 최적해로 간주하지 않는다.

역할 범위: Codex는 환경·실행 코드와 작동 검사를 준비한다. 2026-10-04 사용자가 실제 시뮬레이션의
순차 실행·검토·후속 진행을 Codex에 허가했다. 한 번의 실행을 확인한 뒤 다음으로 넘어가며,
최신 지시에 따라 성능 문제는 보완/후보 기각 후 계속 비교한다. 실행 오류·충돌·teleport·기록 불일치는
중단하고 원인을 확인한다. 큰 웨이브 후 중간 결과를 보고하고 멈춘다.
[보정 웨이브의 후보·계산 한도](adaptive_wave1_20261004.md)를 정하고 기존 모델·결과를 보존한다.
후속 반복 요청으로 [2차 세트·새 기하 전이 평가](adaptive_wave2_20261004.md)를 완료했다.
기존 세 모델의 보정 검증과 새 기하2개·가상 수요12조건의 독립 비교에서 사전 목표를 통과했다.
이후 [경주 연결3교차로의 새 수요6조건 비교](adaptive_gyeongju_wave3_20261004.md)24회도 동결 모델의 재학습 없이 완료했다.
후속 [잔류 차량 진단](gyeongju_drain_wave4_20261004.md)16회에서는 기존 조건/정책을1800초까지 이어가고 처음900초의 원본 일치를 확인했다.
Smart의 잔류353대는1256초 이내 모두 도착했으며 시간 연장 자체를 AI 개선으로 해석하지 않는다.
이는 제한된 적용/개선 증거이며 실제 관측 수요·현장 성능이나 모든 교차로의 최적 신호 검증은 아니다.

2026-10-02 범용 학습 준비: [공통 규격·환경·실행 코드](transferable_signal.md)를 구성했다.
학습7개/검증2개/최종 테스트1개 도로망을 분리하며 최종 테스트에는 경주3교차로가 들어 있다.
Fixed·Webster·Max-Pressure·SmartSignal을 독립적으로 비교한다. 코드 준비 완료와
학습/재학습 없는 적용 성능의 검증 완료를 구분한다. 2026-10-03 사용자가 시작 학습30회를 완료했으며 비교·전이 성능은 미검증이다.

## 현재 기반과 개발 범위

2026-10-05 사용자 피드백: 실측 교통량 확보가 어려워 현장 수요 검증은 보류하고,
[새 가상 교통 상황 검증](diversity_wave5_20261005.md)을 진행한다. 부하 변화·주방향 반전·측면 유입·회전 편중·대형차 비율을 확장하고
동결한 모델로 새 조건을 비교한다. 다양한 가상 조건의 통과는 실제 교통량/현장 성능 검증으로 표시하지 않는다.
이번6종×2표본×4제어48회와 원시 검증을 완료했다. 같은 조건에서 Smart 평균 대기32.686대는
Fixed 대비36.51% 감소했고 도착4297/4417대로 사전 성능 기준을 통과했다. 미완료120대와
Webster 대형차 급제동1건을 기록했으며 추가 학습/모델 변경 없이 이번 큰 세트를 마쳤다.

현재 기반은 단일 교차로 Double DQN, 기본 29D/E2 53D 관측, 고정·Webster 비교,
NumPy 엣지 추론과 단일 교차로 대시보드다. 2026-09-17 SET2에서 경주 교차로3개 도로망과
정적 신호·가상 수요 통행을 검증했다. 다중 교차로 AI·예측·협력·지도 관제는 미구현이다.

완성 기준안:

- 경주에서 선정한 교차로 3개와 연결 도로, 출처·가정을 기록한 수요 시나리오.
- 교차로별 입력·신호 단계에 대응하는 공유 AI와 예측·협력 기능.
- 지도 상태, 교차로 상세, 실험 실행, 성능 비교와 재생이 가능한 웹 관제.
- PC와 Pi의 추론 일치, 처리 시간, 통신 복구 검증.
- 기준선·기능별 비교·미사용 테스트 수요를 포함한 재현 가능한 실험.
- 실행 문서, 시연 자료, 한계를 포함한 결과 설명.

응급차·침수·로드뷰·추가 지역은 핵심 완료 뒤 선택한다.
실제 도로 형태를 사용해도 수요가 가상이면 가상 수요 실험으로 명시한다.

## 진행 순서

| 기간 기준 | 핵심 결과 |
|---|---|
| 1주차 | 기존 기능 점검, 지역 선정, 차량이 정상 통과하는 도로망 |
| 2주차 | 공통 데이터·제어 규칙, 기본 신호와 웹 연결, 평가 기록 |
| 3주차 | 다중 교차로 기본 AI 저장·재로딩·평가 |
| 4주차 | 예측·협력 기능과 기능별 검증 비교, 핵심 기능 고정 |
| 5주차 | 본 평가, Pi 검증, 관제 화면 완성 |
| 6주차 | 오류 수정, 반복 리허설, 발표·전시 자료 |

실제 주차는 작업 시간과 측정한 학습 속도에 따라 조정한다. 정확한 전시일은 아직 미확정이다.

## 역할과 공통 규칙

- 총괄: 범위·목표·우선순위·통합 상태·공통 규칙을 관리한다.
- 환경: 도로·신호·수요·검지기와 교차로 식별자를 제공한다.
- AI: 관측·행동·보상·학습·예측·모델 호환 정보를 관리한다.
- 연결: SUMO 시간 진행, 제어 적용, 서버·Pi 통신을 관리한다.
- 웹: 합의된 상태와 명령으로 지도와 관제 흐름을 구현한다.
- 평가: 기준선·측정 정의·데이터 분리·반복·결과 보존을 책임진다.

구현 전에 교차로 ID, 관측 순서·단위, 행동, 모델 버전, 실험 ID, 시간과 명령 응답을 합의한다.
SUMO 시간 진행과 실제 신호 적용 책임은 한 곳에 모은다.
팀원은 지역 자료 확인, 독립 실행 검증, 시연·발표 자료 정리를 분담할 수 있다.

## 검증 원칙

- 기존 성능 수치는 원본 증거로 보존하되 새 프로젝트의 개선 주장과 분리한다.
- 비교 기법은 같은 도로·수요 일정·회전 조건·신호 전환 제약에서 실행한다.
- Fixed·Webster·상태 반응형 기준선과 기본/개선 AI를 비교한다.
- 학습·검증·최종 테스트 수요를 나누며 최종 테스트로 반복 튜닝하지 않는다.
- 평균 통행·지연뿐 아니라 정차, 긴 대기, 도착·미도착·미진입 차량도 확인한다.
- 예측과 협력의 추가 효과를 분리한다. 여러 요인을 함께 바꾼 경우 그 묶음의 효과로 해석한다.
- 계산 예산 안에서 여러 시드로 반복한다. 개선되지 않은 결과도 기록한다.
