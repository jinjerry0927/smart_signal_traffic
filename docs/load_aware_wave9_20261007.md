# 용량을 고려한 공통 규칙9차

## 실행 전 동결 계획

- 사용자 요청의 보완/평가 반복을 이어간다.8차는120회 원시/별도 감사를 통과했으나 후보3개 모두 기각했다. 최선 balanced25도 대기열−0.88%/도착8대 감소로 사전 기준 미달이었다.8차 소스/결과/선정값None/기존 기본V2를 보존한다.
- 새 가설: 밀도 제한을 단순히 없애는 대신 현재 관측 유입으로 계산한 Webster 녹색 시간을 추가 보호로 쓰고, 대체 방향의 압력이 현재보다2대를 초과해 높고 양수일 때만 AI 유지를 보완하면 혼잡 처리 용량을 지킬 수 있다. 한산한 때의 작은 압력 차이는 현재 접근 차량이 있고 오래 기다린 대기열이 없을 때만 잠시 유지한다.
- 모델43/가중치/안전 제한/AI 기본 행동은 동결한다. 추정 녹색은 하한 보호용이며 Fixed/Webster/Max-Pressure 기준선 소스는 바꾸지 않는다. 미래 수요 파일은 AI 입력으로 쓰지 않는다.
- 후보2개 `load_aware25`, `load_aware30`를 사전 동결한다. 추가 보호 시작은 max(25 또는30초, 현재 관측으로 계산한 해당 상의 Webster 녹색)이다. 기존V2가 먼저 변경하면 그 선택을 유지한다.
- 새 검증:8차의 개발 기하4개에 새97000계열 수요3종×2표본=24조건. Fixed/기존V2/후보2개 =96회. 기존 검증 결과는 원인 진단이며 새 수요로 다시 선정한다.
- 선정 기준은8차와 동일: 평균 대기열 기존V2−2%/Fixed−5% 이상, 도착 수 둘 이상, 기하/수요별 평균 기존V2 대비10% 초과 악화 금지. 통과 후보 중 평균 대기열 최소→도착 최대→후보 선언순으로1개 선정한다. 둘 다 미달이면 이번 큰 세트 중간 검토에서 멈춘다.
- 최종24조건은8차에서 미리 준비했으나 운행/선정에 사용하지 않은6새 기하18조건+경주 새 수요6조건을 그대로 보존해 사용한다. 별도 suite에서 원본 SHA/선정None/최종 출력 미존재를 확인한다. 최종120회는 Fixed/Webster/Max-Pressure/기존V2/선정안, 결과에 따른 재선정 금지. 최종 기준은 선정 기준과 동일.
- 9차 최대216회/후보2개, 각 실행45분 경계. 실제 운행→원시 감사→다음 운행. 오류/충돌/teleport/기록 불일치 즉시 중단·자동 재시도 금지. 급제동 원문은 별도 기록한다.900초 유지, 추가 학습0, 기존 결과 보존, 발표용 비교표 생성0.
- 신호/관측/차량/원시 대기열/소스·모델·입력 SHA를 별도 검증기로 확인한다. 구현 파일은 tools 내부 새 파일이며 기존 package/default/8차 파일을 수정하지 않는다.
