## 오늘 시연 시작

PowerShell 또는 VS Code 터미널에서 아래 명령을 실행하고 터미널을 유지한다.

```powershell
python -X utf8 -B C:/Users/James/.codex/worktrees/f73e/sumo_project/demo_web_pi.py
```

브라우저에서 `http://127.0.0.1:8000`을 연다. 혼잡한 교통 → Smart Signal → PC → 10배 → 실험 시작.
차량·신호·대기 차량이 갱신된다. 교차로 이름으로 지도 확대, 전체 버튼으로3교차로 복귀.
일시정지/재개/정지를 사용할 수 있고 종료 결과는 새 UUID 폴더에 저장된다.
포트8000이 이미 사용 중이면 기존 프로세스를 종료하지 말고 `--port 8001`로 실행한다.

웹에서 현재 운행 지표와 아래의 저장된 최종 비교는 다른 실험이다.
빠른 시연은600초 수요 중 일부만 운행할 수 있으므로 학술 성능 평가로 사용하지 않는다.
종료 시 잔류 차량이 있어도 실행 실패로 간주하지 않는다.

## Pi 연결 (주소 확인 후)

1. 기존 OS/프로젝트를 리셋하지 않는다. PC와 Pi를 같은 로컬 네트워크에 연결한다.
2. Pi에서 `python3 --version`, `python3 -c "import numpy; print(numpy.__version__)"`로 기존 설치를 확인한다.
3. 새 폴더에 내보낸 파일을 복사한다. 같은 폴더가 Pi에 이미 있으면 새 이름을 사용한다. `<SSH_USER>`/`<PI_HOST>`는 실제 확인한 값으로 바꾼다. 암호를 파일에 저장하지 않는다.

```powershell
scp -r results/exports/smart_signal_pi_20261007_v1 <SSH_USER>@<PI_HOST>:~/smart_signal_pi_20261007_v1
ssh <SSH_USER>@<PI_HOST>
```

Pi 터미널에서:

```bash
cd ~/smart_signal_pi_20261007_v1
python3 -B -m signal_demo edge --release release --host 0.0.0.0 --port 9998
```

4. PC 관제에 `http://<PI_HOST>:9998`을 설정한다. 모델/관측/제약/추론 소스의 식별이 모두 맞아야 원격으로 사용한다.
5. 실제 Pi 연결 후 PC 터미널에서 같은 입력의300행동과 통신 지연을 검사한다. 매 검사 출력 파일은 새로운 이름을 사용한다. 주소 미제공 상태에서는 완료로 기록하지 않는다.

```powershell
python -X utf8 -B -m signal_demo probe --url http://<PI_HOST>:9998 --out results/runs/pi_probe_01.json
```

Pi에는 NumPy 추론만 필요하며 SUMO와 학습용 Torch를 설치할 필요가 없다.
이 서비스는 개인 로컬 네트워크 실습용이다. 실제 교통 신호 장비는 제어하지 않는다.
