# 구조 악화·잔류 진단 — 7차 세트

## 실행 전 목표 카드

- 요청: 6차에서 Fixed 대비 악화3조건과 Smart 잔류74대의 원인을 진단한다.
- 담당/분류: 현재 채팅, high. 기존 제어/관측/학습 코드는 변경하지 않고 읽기 전용 진단을 추가한다.
- 선행 증거: 구조6차144회 최종 verify 통과, 모델43/wait35·안전 제한 동결.
- 질문: 악화는 신호 배분/전환과 어느 접근로의 대기에서 발생하는가?
  잔류는 900초 종료 때문인가, 1800초에도 해소되지 않는 정체인가?
- 범위: 전용 진단 실행/검사/원시 재검증/상태·목표 기록. 모델 보완·재학습·재선정·센서 시험은 하지 않는다.
- 입력: 6차 동일 도로망·수요·seed. 유입600초는 유지하고 정리 시간을300→1200초로만 늘린다.
- 대상: t1/busy_s00, t2/busy_s01, x3/busy_s00은 Fixed와 Smart 각1회;
  t3/busy_s01, x3/busy_s01, x3/directional_s00/s01은 Smart 각1회. 총7조건10회.
- 출력: results/runs/structure_diag_wave7_20261007/. 기존 입력/144회 원시 결과/모델은 SHA 보존한다.
- 완료: 관련 검사, 실제10회 순차 실행/매회 원시 확인, 첫900초 원본 지표·차량·신호·경고 재현,
  매초 차로/신호/유입·교차로 진입 기록, 정책 결정 사유, 900/1200/1800초 잔류 차량 스냅샷,
  원인 증거와 미확정 부분 및 별도 최종 검증을 남긴다.
- 중단: 실행 오류/충돌/teleport/기록 불일치면 다음 운행을 중단한다.
  급제동 경고는 원문 보존해 별도 기록한다. 자동 우회/무한 재시도 없음.
- 한도:10회, 완료 경계45분. 동일 입력/소스에서만 중단 재개 가능하다.
- 판단: 전원 배출 시 이 표본의 지속 교착은 관찰되지 않음; 잔류 시 위치/정지/배출 추이를 기록해 미해결로 남긴다.
  1800초 평균과 과거900초 평균을 섞어 AI 성능 개선으로 주장하지 않는다.
- 발표용 비교표: 사용자 요청으로 지금 제작하지 않는다. 나중 요청 시 검증된 원시 결과를 사용할 수 있다.
- Webster 기존 급제동의 상세 원인 재현은 이번 대상 밖이며 미해결 사실을 보존한다.
- 상태: 실제10회·최종 원시 검증 완료. 아래에 확인된 메커니즘과 미확정 범위를 남긴다.

## 결론

기존43/wait35 모델을 그대로 사용한1800초 진단10회를 PowerShell에서 순차 완료했다.
모든 운행의 첫900초는 원래6차와 일치했고, 이후 정리 구간을 관찰했다.
모델/정책/안전 제한을 보완하거나 재학습한 실험이 아니다.

### 잔류74대: 종료 시각이 배출 완료보다 이르다

- 900초 잔류 차량74개의 ID를 원래 unfinished trip과 대조했고 모두 일치했다.
  1200초와1800초에는 전원 도착/운행 중0/삽입 대기0이었다.
- 전원 도착 확인 시점은 t3/busy_s01 **932초**, x3/busy_s00 **914초**,
  x3/busy_s01 **1017초**, x3/directional_s00 **991초**, x3/directional_s01 **1031초**다.
  유입 종료600초 뒤 추가314~431초가 필요했고, 기존 정리300초로는 모자랐다.
- 900초에는33대가 정지 중,41대가 움직이고 있었다.
  위치는 진입 도로44대/교차로 내부3대/통과 후 출구 도로27대다.
  잔류를 모두 정체 차량으로 간주하거나 출구 도로 주행 차량까지 신호 실패로 집계하면 안 된다.
- 이5표본에서 지속 교착은 관찰되지 않았다. 원래900초의 미완료74대는 그대로 보존하며,
  시간을 연장해 전원 도착한 사실을 AI 학습 개선이나 모든 조건의 교착 부재로 확대하지 않는다.

### 최대 악화 t2/busy_s01: 초반 우선순위·녹색 유지와 보호 조건

- Fixed 대비 평균 대기행렬 **+15.18%**는 원본 재현으로 확인했다.
  큐 누적량 차이는1939 차량·초이며, 동쪽 진입로 증가1158 차량·초가 약59.7%를 차지했다.
  나머지는 북쪽385/남쪽396 차량·초다. 차량·초는 매초 대기 차량 수를 더한 진단량이며,
  차량별 SUMO 누적 waitingTime과 같은 지표라고 가정하지 않는다.
- 차이의 대부분은 첫300초에 발생했다(+2283 차량·초).
  301~600초는+113,601~900초는−457이었다. Smart가 뒤에는 더 빨리 정리하지만,
  앞부분에서 만든 대기를 상쇄하지 못했다. 전원 도착은 Smart764초/Fixed814초다.
- 초기 단계 순서는 Fixed가 N→E→S인 반면 Smart는 N→E→N→S였다.
  **남쪽 첫 녹색은 Fixed60초, Smart95초**로35초 늦었다.
  50초에는 저부하 pressure 모드가 E에서 N을 선택했다(pressure N/E/S=2/0/0).
  55초에 평균 밀도가0.10을 넘어 AI 모드로 바뀌었다.
  70~85초에는 동/남쪽에 큐가 생겼는데도 AI가 현재 북쪽 녹색을 유지했다.
- 큐 보호가 동작할 수 있는 녹색25초 경계(80초)에 평균 밀도는0.120688로
  보호 적용 한도0.12를 이미 넘었다. 따라서 `queue_guard_triggered=False`였다.
  90초에 AI가 남쪽을 선택했고 황색3/전체 적색2초 뒤95초에 남쪽 녹색이 시작됐다.
  이 로그는 저/고부하 전환·현재 단계 유지·밀도 제한이 결합한 실패 패턴을 보여준다.
- 첫300초 전환은 Smart8회/Fixed10회, 황색+전체 적색 시간도40초/50초였다.
  **이 조건의 악화를 잦은 신호 전환 탓으로 설명할 수 없다.** 초반 방향 선택·녹색 유지가 핵심 조사 지점이다.
  같은 기간 녹색은 N110/E85/S65초(Smart), N100/E75/S75초(Fixed)였다.
  시간의 총량뿐 아니라 차량 도착 시점에 맞는 배분 순서가 필요하다.
- 전체900초의 출구 도로 정지 큐0, 최대 출구 저장밀도 대리값0.219였다.
  출구 정체로 되밀리는 현상이 주원인이라는 증거는 없었다.
- 특정 신경망 가중치나 임계값 하나의 인과 기여는 이 읽기 전용 재현만으로 확정하지 않는다.
  위 패턴을 보완할 일반 규칙/학습은 별도 검증 조건에서 시험해야 한다.

### 나머지 작은 악화2조건: 방향별 대기 교환과 전환 손실

- t1/busy_s00의+0.13%는 전체 큐 누적6 차량·초 차이다.
  남쪽은+309, 동쪽−282, 북쪽−21로 대부분 상쇄됐다.
  유입600초 동안 남쪽 녹색은 Smart135초/Fixed150초였고,
  Smart는 전원 도착700초로Fixed726초보다 빨랐다.
  작은 평균 악화가 전원 배출도 느리다는 뜻은 아니다. 단일 표본의 유의성은 판단하지 않았다.
- x3/busy_s00의+0.55%는 누적270 차량·초 차이다.
  동/서쪽+3688/+4528 증가를 북/남쪽−4051/−3895 감소가 대부분 상쇄했다.
  유입600초 동안 Smart의 동/서 녹색은95/115초, Fixed는각125초였다.
  북/남쪽을 먼저 더 배분하면서 동/서쪽 대기가 늘어난 패턴이다.
  전체900초 전환은34회/30회로Smart의 황색+전체 적색 시간이20초 더 길었다.
  유입600초만 보면 전환 손실은두 방식 모두100초이므로 전환 증가만으로 전체 악화를 설명하지 않는다.
  Smart는900초 잔류3대/Fixed8대, 전원 배출914초/1011초로 도착·정리에서는 우세했다.

## 변경과 검증

- 신규 `tools/structure_diagnostic.py`: 기존 DrainEnvironment·동결 validated factory를 재사용한다.
  읽기 전용 정책 wrapper는 실제 action을1번 호출해 같은 값을 돌려주며,

  재개 시 소스/입력/완료 기록을 재검증하고 오류·안전 중단 뒤 무검토 재시도는 거부한다.

  진단 폴더 생성 누락은 첫 가짜 검사에서 발견해 생성 코드를 보완했다. 실제 운행 전 수정/재검사 완료.

  각 운행 후 원본900초 지표(기록 지연에 영향을 받는 실행시간 제외)/완료 차량 속성/잔류 ID/
