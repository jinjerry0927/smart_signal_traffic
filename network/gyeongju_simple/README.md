# 산업로 지도 정리형 SUMO 환경

사용자가 선택한 **지도 정리형**을 SUMO 도로망에 반영했다. 용강 → 근화여고 → 승삼이
북동쪽으로 이어지고, 사이 도로와 외곽 진출입은 완만하게 굽는다. 교차로 가까이는
직선으로 정돈해 차선·정지선·회전 방향이 잘 보이게 했다. 건물이나 추가 갈림길은 없다.
기존 실행 경로 `gyeongju_simple`을 그대로 사용한다. 정밀형은 `../gyeongju_industrial/`에 보존한다.

## 열기

이 폴더의 **open_sumo.cmd를 더블 클릭**한다. 실행 위치와 무관하게 설정을 찾는다.
SUMO 창에서 ▶를 누르면 예시 차량이 움직인다. 화면 확대 시 차선·회전 화살표·신호가 보인다.

PowerShell에서는 다음 전체 경로를 사용할 수 있다.

```powershell
sumo-gui -c "C:\Users\James\.codex\worktrees\f73e\sumo_project\network\gyeongju_simple\demo.sumocfg"
```

## 도로·차선·신호

- 교차로3개, 외부 진출입8개, 방향별 도로20개·차로30개. 곡선은 도로 모양만 바꾸며
  추가 교차로·신호·분기 경로를 만들지 않는다.
- 간선은 방향별2차로, 측면 지선은 방향별1차로. 기존 모델의 가정이며 현장 확정 차로 수가 아니다.
- 2차로 접근의 바깥 차로는 우회전/직진, 안쪽은 직진/좌회전이 기본이다.
  용강 남동측에서 서측1차로로 직진할 때는 바깥 차로만 직진하고 안쪽은 좌회전한다.
- 1차로 접근은 좌·직·우회전을 함께 허용한다. U턴은 제외했다.
- 교차로별4개 보호 녹색 단계: 북→동→남→서 접근 순환. 녹색25초·황색3초·전체적색2초,
  주기120초인 예시 설정이다. 실측 신호 또는 최적화 결과가 아니다.
- 한 번에 한 접근 방향만 보호 녹색을 받는다. 같은 차로에서 갈라지는 회전은 같은
  신호로 묶었다. 단계 이름 `N_green`, `N_yellow`, `N_all_red` 등으로 방향과 전환을 확인한다.
- 밝은 배경, 차선 경계·방향 화살표·교차로 이름을 표시한다. 배경 지도 타일이나 건물은 사용하지 않는다.
- 예시 차량56대(승용차·버스·화물차)를4초 간격으로 출발시키는 입력 파일을 포함했다.
  실제 교통량이나 학습용 데이터가 아니다.

## 수정과 재생성

`layout.json`에서 좌표·차로 수·도로 이름·신호 시간을 수정한다. 교차로 ID는 기존 구간과 같다.
SUMO 좌표는 **실험용 평면 좌표**이며 실제 위도·경도로 변환하면 안 된다.
`via`는 굴곡의 기준점, `curve_radius_m`은 모서리 앞뒤를 다듬는 거리(현재90m),
`curve_step_m`은 곡선 점 간격의 상한(현재5m)이다. 도로 끝점과 교차로 진입 방향은 유지한다.

```powershell
# 저장소 루트에서 실행; 도로 생성과 정적 연결 검사만 수행한다.
python tools/build_gyeongju_simple.py --overwrite
# 도로·차로·신호·경로의 정적 검사만 수행한다.
python -B tests/test_gyeongju_simple.py
# 운행 없이 설정을 로드한다.
sumo -c network/gyeongju_simple/demo.sumocfg --end 0 --no-step-log true
```

`nodes.nod.xml`·`roads.edg.xml`·`turns.con.xml`·`signals.tll.xml`을 netconvert에 넣어 생성한다.
[SUMO PlainXML 공식 문서](https://sumo.dlr.de/docs/Networks/PlainXML.html).
생성된 `simple.net.xml`을 직접 수정하는 대신 입력 설정을 수정한다.

`contract.json`에 차로별 허용 회전·신호·경계·56개 경로를 기록했다. 도로 ID와 좌표 체계는
정밀형과 다르므로 이전 실험 러너나 단일 교차로 AI를 그대로 연결하지 않는다.
향후 다른 교차로에 적용할 공통 관측·행동 인터페이스 설계에 사용할 환경이다.

## 확인 범위 (2026-10-02)

빌더와 정적 검사4개 통과: 신호3개, 차로30개, 차로별 회전42개,
모든56개 OD 연결(승용차·버스·화물차), 급격한 차로 꺾임 없음,
동시 보호 녹색의 충돌 관계 없음, 같은 차로의 회전 신호 일치, 황색·전체적색 전환 확인.
`sumo --end 0` 및 `sumo-gui --start --end 0 --quit-on-end` 로드 통과.
중단 후 최종 확인에서도 정적 검사4개와 설정 로드가 통과했으며, 별도 폴더에서 다시 생성한
출력11개(`nodes`·`roads`·`turns`·`signals`·도로망·계약·예시 차량·설정·화면·이름표·실행 파일)가
현재 환경과 바이트 단위로 일치했다. `git diff --check`도 통과했다.
차량 운행·혼잡 시나리오·학습·성능 평가는 실행하지 않았다.
정적 연결 확인이 실제 운행 중 충돌·정체·대기시간 평가를 대신하지는 않는다.

다음 단계는 사용자가 `open_sumo.cmd`로 열고 배치를 확인한 뒤 예시 차량이나 직접 준비한
수요를 실행하는 것이다. 실제 차로 수·교통량·신호 시간의 현장 확인은 남아 있다.
